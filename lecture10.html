Preparing the data 1: text to ids and vectors

Vocabulary: <pad> → 0, not → 1, be → 2, or → 3, to → 4

Preparing the data 2: cut into sequences, pad, shift

Each row is one training sequence with T = 5 inputs. Padding (id 0) fills the last one; padded targets are ignored by the loss. With separate sentences, pad each one to the longest sentence (the max length).

Training: every sequence, many epochs

Each sequence: forward pass, loss, BPTT, one update of the shared weights. One pass over all sequences is an epoch; reshuffle and repeat until the loss stops falling.

In PyTorch: preparing the data

import torch, torch.nn as nn, torch.nn.functional as F
from torch.utils.data import TensorDataset, DataLoader

words = open("hamlet.txt").read().split()
vocab = ["<pad>"] + sorted(set(words))   # id 0 = padding
stoi  = {w: i for i, w in enumerate(vocab)}
ids   = torch.tensor([stoi[w] for w in words])

T = 20                                  # inputs per sequence
seqs = list(ids.split(T + 1))           # chunks of T+1 ids
seqs[-1] = F.pad(seqs[-1], (0, T + 1 - len(seqs[-1])))
data = torch.stack(seqs)                # (N, T+1)
X, Y = data[:, :-1], data[:, 1:]        # inputs, targets
loader = DataLoader(TensorDataset(X, Y), batch_size=32,
                    shuffle=True)

In PyTorch: the model

class RNNLM(nn.Module):
    def __init__(self, V, d=32, H=128):
        super().__init__()
        self.embed = nn.Embedding(V, d, padding_idx=0)
        self.rnn   = nn.RNN(d, H, batch_first=True)  # tanh
        self.head  = nn.Linear(H, V)

    def forward(self, x, h0=None):
        e = self.embed(x)            # (B, T) → (B, T, d)
        out, hT = self.rnn(e, h0)    # every h_t: (B, T, H)
        return self.head(out), hT    # logits: (B, T, V)

nn.Embedding: id → vector xt.

nn.RNN: the recurrence for ht with Wxh, Whh, bh, shared over time.

nn.Linear: the readout Why, by → a score per vocabulary word.

In PyTorch: training over epochs

model   = RNNLM(len(vocab))
opt     = torch.optim.Adam(model.parameters(), lr=1e-3)
loss_fn = nn.CrossEntropyLoss(ignore_index=0)  # skip padding

for epoch in range(20):                  # many passes
    for xb, yb in loader:                # (B, T) ids
        logits, _ = model(xb)            # forward
        loss = loss_fn(logits.reshape(-1, len(vocab)),
                       yb.reshape(-1))   # mean loss
        opt.zero_grad()
        loss.backward()                  # BPTT
        nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        opt.step()                       # one update
    print(epoch, loss.item())

CrossEntropyLoss averages over batch × time, so the gradient is the average from the BPTT slides.

loss.backward() runs BPTT through the unrolled graph.

clip_grad_norm_ caps the gradient size against exploding gradients.

Generating text: predictions are fed back

Start from a prompt, then repeat: compute , pick a token, feed it back as the next input.

One wrong token can derail the whole text

  • In training (teacher forcing) the model always saw the true history. Now it conditions on its own output, mistakes included: a situation it never saw.
  • Errors compound: if each token is right with probability 0.95, the chance of no mistake is 0.60 after 10 tokens, 0.36 after 20, and 0.08 after 50.

Small errors grow in numeric sequences too

Ways to reduce it: sample carefully (temperature, beam search), train on some of the model’s own predictions (scheduled sampling), and use models with better memory.

Long sequences: the clue can be far back

Why the gradient fades over long sequences

Shading = size of the gradient from the loss at ? reaching each word, if each factor scales it by ρ. Since tanh′ ≤ 1, a Whh that shrinks vectors gives ρ < 1.

The fix: give the gradient a shortcut

  • A product of terms like does not shrink to zero the way a product of small Jacobians does.
  • The same trick as residual connections across layers, applied across time. The LSTM builds its memory around such an additive path.

LSTM: a cell state that is updated by addition

A pure residual path could never forget. The LSTM learns gates between 0 and 1 that decide what to keep (ft), what to write (it) and what to reveal.

Both add terms, so why is only the LSTM residual?

Vanilla RNN

The old state is multiplied by a full learned matrix and squashed by tanh at every step. This is the identity only if and tanh′ = 1.

LSTM cell

The old state is not multiplied by a matrix and not squashed, only scaled entry by entry by a gate. With this is the identity.

The original LSTM (1997) had no forget gate: , an exact residual update. The forget gate was added later so the cell can also erase. The gates depend on too, which adds indirect gradient paths; the direct path above is what keeps gradients alive.

Training an LSTM: still BPTT

  • Unroll, forward pass, loss at every step, backward through time, average the gradients, update: exactly as for the RNN.
  • Along the cell path the gradient is only scaled by at each step, with no or tanh′ in between, so it survives many more steps.
  • Gradients can still explode, so gradient clipping stays in the loop.

Sequence → label: sentiment classification

Read the whole review first; only the final state , a summary of everything read, is classified.

Training a sequence classifier

  • One label per sequence, so one loss, at the last step.
  • BPTT carries it back through every step; the earliest words get the weakest gradient. Use an LSTM/GRU, or pool all states (mean or max of the ).
  • With padded batches, classify the state at each review’s last real token (pack_padded_sequence).
class SentimentRNN(nn.Module):
    def __init__(self, V, d=64, H=128, n_classes=2):
        super().__init__()
        self.embed = nn.Embedding(V, d, padding_idx=0)
        self.rnn   = nn.LSTM(d, H, batch_first=True)
        self.head  = nn.Linear(H, n_classes)

    def forward(self, x):                   # (B, T) ids
        _, (hT, _) = self.rnn(self.embed(x))
        return self.head(hT[-1])            # (B, classes)

Sequence → sequence: the encoder–decoder

  • The encoder RNN reads the input and compresses it into one context vector .
  • The decoder is a second RNN, started from , that generates the output token by token until <eos>. Input and output lengths can differ.

Training and using an encoder–decoder

  • Training: teacher forcing on the target. Decoder input <bos>, y1, …, yK; targets y1, …, yK, <eos>. Cross-entropy averaged over output tokens; one BPTT through decoder and encoder.
  • Inference: autoregressive, as before. Greedy or beam search; stop at <eos>.
  • Bottleneck: the whole input must fit in one fixed vector , so long inputs lose detail. Attention lets the decoder look back at every encoder state, the step that leads to Transformers.

Beam search: keep the k best partial outputs

Score = product of probabilities (sum of log-probabilities), usually divided by length so short outputs are not favoured. k = 1 is greedy decoding; a larger k searches more at about k× the cost.
